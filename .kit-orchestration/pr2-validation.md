## Issues Found
- REJECT — `.kit-orchestration/pr2-plan.md:95` and `.kit-orchestration/pr2-plan.md:158`: `timeout` is not portable to default macOS. GNU documents `timeout` as a Coreutils command, and Homebrew installs Coreutils with `g`-prefixed commands unless `gnubin` is added to `PATH`: https://www.gnu.org/software/coreutils/timeout and https://formulae.brew.sh/formula/coreutils. The script should resolve `timeout`/`gtimeout`, provide a fallback, or avoid requiring it.
- REJECT — `.kit-orchestration/pr2-plan.md:107`: `flock` is not available by default on macOS as a shell utility; Linux `flock(1)` is from util-linux: https://man7.org/linux/man-pages/man1/flock. Use a portable `mkdir` lock directory with `trap` cleanup, or detect `flock` and fall back. If `flock` is missing today, the script misleadingly reports “another dispatch.sh run is in progress”.
- REJECT — `.kit-orchestration/pr2-plan.md:91-99`: the auth preflight is too narrow and potentially flaky. Five seconds can false-fail on slow startup/auth/network, `timeout` may be missing, and the preflight does not pass `-m "$MODEL"`, so it can succeed while the requested model later fails for auth/model availability. Make the timeout configurable, use the resolved timeout command, and preflight the actual target model.
- REJECT — `.kit-orchestration/pr2-plan.md:165`: `codex exec ... "$(cat "$PROMPT_FILE")"` risks `ARG_MAX` for large specs/blueprints. Local `ARG_MAX` is 3,200,000 bytes, and real prompt bundles can approach this. Use stdin: `codex exec ... - < "$PROMPT_FILE"`.
- REJECT — `.kit-orchestration/pr2-plan.md:273-275`: executor instructions conflict: “git commit” necessarily writes `.git/`, but the next bullet says “Do NOT modify .git/.” Clarify “do not manually edit `.git/`; normal `git commit` metadata writes are allowed.”
- REJECT — `.kit-orchestration/pr2-plan.md:122-140`: tmux resolution does not reliably mean “the user’s current Claude terminal”. It chooses the most recently active attached client globally; with multiple clients, that may be a different terminal/session. With zero clients and an existing detached session it correctly falls back to inline, but the docs should state detached sessions are ignored unless `KIT_TMUX_SESSION` is set. Prefer `#{client_session}` over `#{session_name}` for `list-clients` clarity.
